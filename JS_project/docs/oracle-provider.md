# Oracle provider

Oracle Database подключается как дополнительный provider и по умолчанию не установлен.

## Пользовательский сценарий

1. Открыть **Настройки → Поддерживаемые СУБД**.
2. Включить **Oracle Database**.
3. Проверить сведения в окне подтверждения и нажать **Скачать и включить**.
4. После успешной проверки сохранить настройки.
5. В форме нового подключения выбрать **Oracle Database** и один из режимов:
   - **Service name** — сервер, порт и зарегистрированное имя сервиса;
   - **SID** — сервер, порт и системный идентификатор экземпляра;
   - **Connect descriptor / URL** — Easy Connect, `(DESCRIPTION=...)` либо JDBC URL, скопированный из DBeaver/DataGrip. Поддерживаются формы `jdbc:oracle:thin:@//host:port/service` и `jdbc:oracle:thin:@host:port:SID`.
6. Указать пользователя и пароль, затем выполнить проверку подключения.

Ошибка `NJS-518` означает, что listener доступен, но переданный Service name не зарегистрирован. В этом случае нужно уточнить у DBA правильный Service name либо выбрать SID/полный descriptor в соответствии с параметрами рабочего подключения DBeaver или DataGrip.

## Источник и проверка

- пакет: Oracle `node-oracledb` 7.0.1;
- режим: Thin;
- официальный источник: `https://registry.npmjs.org/oracledb/-/oracledb-7.0.1.tgz`;
- SHA-512 закреплена в `desktop/src/provider-installer.js`;
- после распаковки дополнительно проверяются имя `oracledb` и версия `7.0.1`;
- provider хранится в `%APPDATA%\DB Tools\providers\oracle-7.0.1` и не содержит паролей.

Thin mode работает с Oracle Database 12.1 и новее без Oracle Instant Client. Поддержка старых серверов и Thick mode в эту итерацию не входят.

Технический журнал записывает только начало, окончание или ошибку установки provider. URL подключения, пользователь, пароль, SQL и результаты запросов в него не передаются.
