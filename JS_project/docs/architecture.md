# Архитектура

## Границы доверия

React не получает пароли и не открывает соединения. `app/server` валидирует запрос, применяет timeout/лимиты, выбирает установленный provider и возвращает нормализованный результат. В текущем срезе transport намеренно mock-only.

`pg-tools` работает только через переданный host API. Он не устанавливает драйверы, не хранит учётные данные и не создаёт соединения.

## Provider model

Провайдер описывается стабильным runtime-контрактом: `id`, совместимость, возможности и фабрика executor. PostgreSQL — первый descriptor. Другие СУБД добавляются отдельными workspace/npm-пакетами без ветвления UI по имени СУБД.

В production installer должен получать allowlist из подписанного каталога, скачивать пакет только из официального registry/vendor URL, проверять точную версию, SHA-256 и подпись до установки. Выбор пользователя хранится отдельно от секретов и может меняться в настройках.

## Данные

Профили подключений хранят только несекретные поля; секреты — в системном credential store. Каталог SQL и журнал имеют версионированную схему. Никакие форматы старого приложения не используются.

## Выполнение

Каждый запуск получает `requestId`, `connectionId`, SQL, timeout и row limit. Backend/host поддерживает cancel по `requestId`. По умолчанию разрешён один statement, установлен лимит строк и timeout. Ошибки нормализуются и не раскрывают connection string или секреты.
